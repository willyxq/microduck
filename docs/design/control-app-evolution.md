# MicroDuck App 三层演进方案

状态：产品方向草案 · 日期：2026-09-12

## 1. 不变的产品骨架

三个层次不是三款 App，而是同一款 App 随设备能力逐步演进。为避免用户反复学习，底部导航从第一版起统一为：

**首页 / 互动 / 模型 / 设置**

- **首页**回答“鸭子现在怎么样、有没有需要处理的事”。
- **互动**回答“我现在想和它做什么”，从基础动作逐步演进为高级意图和陪伴。
- **模型**负责能力版本、更新、回退与来源说明。
- **设置**负责连接、健康、隐私、权限和设备管理。

始终保留两个安全入口：**立即停止**和**手动接管**。智能提高只会降低它们的使用频率，不会取消它们。

## 2. 第一层：基础控制

定位：先把设备连接、更新和最小互动做可靠，App 是“现场管理员”。

### 主要功能

- BLE 发现、认证、配网、健康、模型更新和回退。
- 互动页显示摄像头、停止、坐下/站起、叫一声。
- 手动驾驶属于调试能力；`teleop` 未完成时显示禁用，不允许降级为 BLE 控制。
- 实体手柄继续承担需要盲操和连续摇杆的现场驾驶。

### 进入第二层的标准

必须同时满足：

1. 设备能稳定完成不少于 5 个高级意图，例如“过来、跟随、自己玩、找球、休息”。
2. 每个意图成功率达到 90% 以上，并能解释拒绝或失败原因。
3. 障碍规避、掉线停车、人工停止经过真机验收。
4. 用户测试中，至少 70% 的互动可在不打开手动驾驶的情况下完成。

## 3. 第二层：意图控制

定位：用户不再“开鸭子”，而是告诉它“要做什么”。

### 主要功能

- 互动首页根据环境提供“跟着我、过来、找球、自己玩、休息”等情境化指令。
- 一次点击启动任务，持续显示“已理解 / 正在执行 / 为什么停下”。
- 摄像头用于确认环境，不占据默认首屏。
- 手动接管降为二级入口；停止仍固定可见。
- 模型页开始说明“这个版本改善了什么行为”，而不只显示技术版本。

### 进入第三层的标准

必须同时满足：

1. 鸭子能连续自主运行 30 分钟以上，不依赖人工纠偏且无安全事件。
2. 关键自主行为成功率达到 95%，误触发率低于 1%。
3. 具备情境、偏好和近期事件记忆，并允许用户查看、纠正和删除。
4. 能清楚展示当前目标、依据和停止原因，不形成不可解释的自主行为。
5. 一半以上活跃用户的日常会话不再使用手动接管。

## 4. 第三层：自主陪伴

定位：App 从控制台变成“共同生活的窗口”；用户设边界、看状态、偶尔召唤和接管。

### 主要功能

- 首页展示情绪、精力、正在做什么和需要用户处理的事项。
- 互动页以“叫它过来、一起玩、安静一会”为主，不展示动作按钮墙。
- 展示活动故事和记忆，并提供纠正、删除及隐私开关。
- 用户设置活动区域、安静时间、摄像头权限和自主程度。
- 手动接管保留在明确入口；立即停止始终一触可达。

## 5. 层次切换原则

切换由**设备能力和安全证据**决定，不由发布日期或营销名称决定。功能可以灰度开放，但同一只鸭子必须根据已安装模型、传感器健康和验收等级，清楚标明当前层次。

如果能力降级、传感器异常或新模型未通过健康门，App 自动退回上一层交互，不假装智能仍然可用。升级和降级都不改变四个底部入口，只改变“互动”页内的主任务。
